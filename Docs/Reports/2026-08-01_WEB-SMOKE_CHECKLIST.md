- 날짜: 2026-08-01
- 근거: [DEVELOPMENT_ORDER.md](../Design/DEVELOPMENT_ORDER.md) 인프라 체크포인트 (F04 예정 → F07 시점에 이행), 기획서 20장 "1일차 Web 빌드", 기획서 15장 Web 제약
- 대상: `Assets/_Game/Scenes/Gameplay/FirstPlayable.unity` (F01~F07 상태)

> **왜 미리 쓰는가**: 빌드가 열리는 것만 보고 "돌아간다"고 결론 내면 스모크 빌드의 목적이 사라진다.
> 지금까지 두 번의 플레이테스트로 잡은 튜닝(가속 1.0s, 넉백 20, DMG-005 최소 간격)이 **전부 물리·시간 기반**이므로,
> WebGL에서 물리나 프레임이 다르면 그 튜닝이 무효가 된다. 그걸 확인하는 게 이번 목적이다.

## 실패 시 판단 기준

- **W4·W5가 깨지면** → 조작 튜닝을 WebGL 기준으로 다시 잡아야 한다. **F08보다 우선**한다
- **W6이 깨지면** → DMG-005 최소 간격(0.5s)을 WebGL 기준으로 재조정. 플레이테스트 재실행
- **W8이 깨지면** → 드론 상한(30)·풀링·물리 설정을 재검토. P11이 아니라 **지금** 처리해야 한다
- **W9만 깨지면** → 지금은 그레이박스라 여유가 있을 것. P11로 이월하되 수치를 기록해 추세를 본다
- **W3에 사소한 경고만 있으면** → 기록하고 통과

## 관측 방식

- W4·W5·W6·W7·W10은 **사람이 직접 플레이**해야 판단 가능 → `MANUAL_REQUIRED`로 표시하고 사용자에게 넘긴다
- W1·W3·W8·W9는 자동 관측 가능 (빌드 로그, 브라우저 콘솔, 파일 크기)
- **에디터와의 비교**가 핵심이므로, 같은 조작을 에디터에서도 한 번 해보고 대조할 것
