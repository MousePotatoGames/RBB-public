# Playtest — F09 Crusher Spike

- 일자: 2026-08-05
- 플레이어: 사용자 1명, 에디터 플레이 모드
- 선행 조건: 입력 장치 문제(A4) 해결 후 첫 정상 플레이

## Observation

- **"잘 된다"** — 조작·전투 전반에 대해 문제 보고 없음
- 이전 플레이테스트(2026-08-01)에서 제기됐던 "두두두 버벅임"(히트스톱 중복)에 대한 재보고 없음
- 프레임 드랍·카메라·조작감에 대한 불만 없음

## 확인되지 않은 것 (중요)

F09의 Manual play checks 6개를 개별로 물었으나, 답변은 **전체에 대한 총평 한 줄**이었습니다.
따라서 아래는 여전히 **미확인**입니다 — "문제 없음"과 "확인됨"은 다릅니다.

| 항목 | 상태 |
|---|---|
| HYP-005 부착 위치가 의미 있게 느껴지는가 | **UNCONFIRMED** |
| 스파이크 쪽 / 반대쪽 차이가 체감되는가 | **UNCONFIRMED** |
| 대시 + 스파이크 정면이 결정타로 느껴지는가 | **UNCONFIRMED** |
| 원뿔 반각 60°가 적절한가 | **UNCONFIRMED** |
| 10초까지 생존 가능한가 / 무기를 몇 개 얻었는가 | **UNCONFIRMED** |

특히 마지막 항목은 R1(무기 도달 가능성)의 판정 근거라서, 다음 플레이 때 반드시 필요합니다.

## Hypotheses

문제 보고가 없으므로 새 가설은 세우지 않습니다. 다만 검증에서 나온 수치 기반 우려는 유지합니다:

- **R1** — 무입력 기준 10.54초 사망 vs 캡슐 스폰 10/35/60초. 2·3번째 무기 도달이 의심스럽다
  (실제 플레이 데이터가 없어 아직 가설 단계)
- **R3** — 흰 공 + 회색 무기라 무기가 붙은 게 시각적으로 잘 안 읽힐 수 있다

## Next Experiment

**이번엔 튜닝 변경을 하지 않습니다.** 바꿀 근거가 없습니다 — 불만이 없고, R1은 아직 관측이 아니라 계산입니다.

다음 플레이 때 **딱 하나만 측정**합니다:

1. 한 판 끝까지 플레이한다
2. **생존 시간**과 **획득한 무기 개수**를 기록한다 (결과 화면의 `TIME`으로 확인 가능)
3. 3판 반복

## Success Criteria

- 3판 중 **최소 1판에서 무기 2개 이상** 획득 → R1은 기우, `spawnTimes` 유지
- 3판 모두 **무기 1개 이하** → R1 확정, `WeaponConfig.spawnTimes`를 단일 변수로 조정

이 실험은 **코드·수치를 아무것도 바꾸지 않으므로 되돌릴 것이 없습니다.**
